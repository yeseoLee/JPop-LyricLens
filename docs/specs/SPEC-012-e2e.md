# SPEC-012 E2E 브라우저 테스트와 스크린샷

- 상태: 진행 중
- 이슈: #29
- 구분: MVP 검증
- 대응 요구사항: PRD 4장 — F2008~F2012 화면 증명, NF2004
- 관련 절: `docs/verification.md` §5

## 1. 목적
실제 브라우저로 앱을 조작해 사용자 시나리오가 끝까지 동작하는지 확인하고, 검증 문서와 PR에 붙일 스크린샷을 남긴다.

## 2. 범위
- 포함: Playwright(Python) 기반 `tests/e2e/`, 앱 서버 기동 픽스처, 시나리오 7개, 스크린샷 저장(`docs/e2e/`), 검증 문서 갱신
- 제외: CI 실행 (실제 GMS 키·색인·브라우저가 필요) → `@pytest.mark.e2e` 로 표시하고 CI에서 제외

## 3. 상세 설계

### 3.1 빌드·기동 (픽스처 `app_url`)
1. 사전 조건 확인: `GMS_KEY`·`WIKI_CONTACT` 설정, `song_meta` 색인 ≥ 1 — 없으면 `pytest.skip` 과 이유
2. `streamlit run src/lyriclens/ui/app.py --server.headless true --server.port <빈 포트>` 를 하위 프로세스로 띄움
3. `/_stcore/health` 가 `ok` 를 줄 때까지 최대 60초 대기, 끝나면 프로세스 종료
4. 브라우저: Playwright Chromium 헤드리스, 화면 1440×1000

### 3.3 실행
```bash
pip install -r requirements-dev.txt     # playwright 포함
python -m playwright install chromium   # 브라우저가 없을 때만
pytest -m e2e tests/e2e -s
```
- 스크린샷은 `docs/e2e/` 에 덮어쓴다. PR 본문에는 스크린샷을 커밋한 SHA 기준 링크로 넣는다(브랜치 삭제 후에도 유지).

## 5. 실행 결과 (2026-10-21)
- 7개 시나리오 모두 통과 (50초). 실제 키·색인을 복사한 별도 데이터 디렉터리(`LYRICLENS_SETTINGS`)에서 실행해, 백그라운드 미리 수집과 충돌하지 않게 했다.
- 처음 실행에서 결과가 그려지기 전에 확인하는 대기 문제와 Streamlit 1.62의 카드 요소 차이로 2개가 실패 → 결과 요소가 나타날 때까지 기다리도록 테스트를 고침. 앱 코드는 바꾸지 않음.
- 실패한 시나리오는 `docs/e2e/failed_<이름>.png` 를 남긴다(커밋하지 않음).
