# SPEC-013 한국어 번역 제목 곡 문서를 1차 문서로 인정

- 상태: 진행 중
- 이슈: #30
- 구분: MVP 개선
- 대응 요구사항: F2004 ("선택한 항목 자체를 다룬 문서는 어떤 제외 규칙보다 우선하여 항상 색인")
- 관련 절: `docs/specs/SPEC-004-wiki-collect.md` §3.5-2, `docs/verification.md` §8 한계 1

## 1. 문제
한국어 위키백과의 곡 문서 제목이 번역 제목인 경우가 있다(「夜に駆ける」 → 「밤을 달리다」). 지금은 제목이 곡 제목과 같거나 `곡 제목 (` 로 시작할 때만 곡 문서로 인정한다. 그래서 이런 문서는 1차 문서가 되지 못하고, 선별 단계가 버리면 아예 빠진다.

## 2. 설계
곡 문서 찾기(`find_song_page(song, wiki, limit, verify_limit)`)를 다음 순서로 바꾼다.
1. **후보 모으기**: `find_page(title)`(리다이렉트 포함) → `search(title)` → `search(f"{title} {artist_query}")` → `search(f"{artist_query} 노래 {title}")`. page_id 중복은 제거한다. **동음이의어 문서**(제목에 `동음이의` 가 들어감)는 뺀다.
2. **제목 규칙 1차 통과**: 전체 후보 중 제목이 다음 중 하나면 곧바로 곡 문서다. 본문은 받지 않는다.
   - 곡 제목과 같거나 `곡 제목 (` 로 시작
   - 괄호 안에 아티스트(한국어 표기 또는 원어)와 `노래`·`곡`·`싱글` 중 하나가 있음 (예: `아이돌 (요아소비의 노래)`)
3. **본문 확인 2차**: 1차에서 못 찾으면 앞에서 `collect.primary_verify_limit`(기본 3)개 후보의 본문을 받는다. **곡 제목과 아티스트 이름(한국어 표기 또는 원어)이 모두 본문 앞 2,000자 안에 있으면** 곡 문서로 인정한다(예: `밤을 달리다`). 받은 본문은 다시 받지 않도록 함께 넘긴다.
4. 모두 실패하면 지금처럼 아티스트 문서가 곡 문서 역할을 한다.

- 실제 위키백과로 확인한 결과(2026-10-21), 본문 확인만 쓰면 동음이의어 목록 문서(`레몬 (동음이의)`)가 곡 제목과 아티스트를 함께 언급해 통과했다. 그래서 동음이의어 제외와 제목 규칙 우선을 넣었다.
- 설정 추가: `collect.primary_verify_limit: 3`
