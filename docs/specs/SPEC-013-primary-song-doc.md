# SPEC-013 한국어 번역 제목 곡 문서를 1차 문서로 인정

- 상태: 진행 중
- 이슈: #30
- 구분: MVP 개선
- 대응 요구사항: F2004 ("선택한 항목 자체를 다룬 문서는 어떤 제외 규칙보다 우선하여 항상 색인")
- 관련 절: `docs/specs/SPEC-004-wiki-collect.md` §3.5-2, `docs/verification.md` §8 한계 1

## 1. 문제
한국어 위키백과의 곡 문서 제목이 번역 제목인 경우가 있다(「夜に駆ける」 → 「밤을 달리다」). 지금은 제목이 곡 제목과 같거나 `곡 제목 (` 로 시작할 때만 곡 문서로 인정한다. 그래서 이런 문서는 1차 문서가 되지 못하고, 선별 단계가 버리면 아예 빠진다.

## 2. 설계
곡 문서 찾기(`find_song_page(song, wiki, limit)`)를 다음 순서로 바꾼다.
1. `find_page(title)`(리다이렉트 포함)의 결과가 제목 규칙에 맞으면 곡 문서로 쓴다.
2. 아니면 후보를 모은다: `find_page` 결과(있으면) → `search(title)` → `search(f"{title} {artist_query}")`. page_id 중복은 제거하고 앞에서 최대 `collect.primary_verify_limit`(기본 3)개만 본다.
3. 후보마다:
   - 제목 규칙에 맞으면 바로 곡 문서
   - 아니면 본문을 받아 **곡 제목과 아티스트 이름(한국어 표기 또는 원어)이 모두 본문 앞 2,000자 안에 있으면** 곡 문서로 인정한다. 이때 받은 본문은 다시 받지 않도록 결과에 함께 넘긴다.
4. 모두 실패하면 지금처럼 아티스트 문서가 곡 문서 역할을 한다.

- 동음이의어 방지: 제목만 같은 다른 문서(예: 과일 「레몬」)는 아티스트 이름이 본문에 없어서 걸러진다.
- 설정 추가: `collect.primary_verify_limit: 3`

## 3. 수용 기준 (AC)
| 테스트 ID | 조건 | 기대 결과 |
|-----------|------|-----------|
| T-F2004-9 | 곡 문서가 번역 제목(「밤을 달리다」)이고 본문에 원제·아티스트가 있음 | `is_primary=True` 로 수집, 본문은 한 번만 fetch |
| T-F2004-10 | 리다이렉트 결과가 동음이의어 문서(아티스트 언급 없음) | 곡 문서로 인정하지 않음 |
| T-F2004-11 | 검증 대상은 최대 `primary_verify_limit` 개 | 그 이상 fetch 하지 않음 |
| live | 「夜に駆ける」 실제 수집 | 「밤을 달리다」가 1차 문서 |
