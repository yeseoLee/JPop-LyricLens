# 벤치마크 결과

검색과 답변 품질을 같은 기준으로 비교하기 위한 벤치마크입니다. 케이스·지표 정의는 `docs/specs/SPEC-015-benchmark.md` 에 있습니다.

- 실행: `python scripts/bench_build.py` → `python scripts/bench_run.py search|qa`
- 원자료: `data/bench/results/*.json` (커밋하지 않음)
- 환경 (2026-10-21)
  - 모델: 답변 `gpt-6-luna`, 보조 작업 `gpt-5.4-nano`, 임베딩 `text-embedding-3-large`, 판정 `gpt-6-luna`
  - 데이터: 곡 240곡, 1차 문서 미리 수집 완료

**해석**
- **잘 알려진 곡(normal 60)** 은 RAG 없이도 정답률 0.98이다. 모델이 이미 아는 사실이라 이 문항만으로는 정확성 차이가 보이지 않는다. 첫 측정(60문항)에서 이를 확인하고 어려운 문항을 추가했다.
- **어려운 문항(hard 30)**: RAG 없이 정답률 0.07, 오답률 0.50이었다. 없는 편곡자(「大橋ちひろ」·「山下洋介」)를 지어내거나 아티스트 본인을 편곡자로 답했다. RAG를 쓰면 키워드 기준 1.00, LLM 판정 0.93이다.
- **답할 수 없는 질문**: RAG 없이 모름 인정률 0.67(4/12는 지어냄), RAG를 쓰면 1.00이다.
- **근거 제시율**: RAG 0.93. 근거 없이 답한 경우는 "확인되지 않습니다" 응답이다.
- **가사 의미(meaning)**: RAG가 0.70으로 RAG 없음(0.90)보다 낮다. 근거에 없는 해석을 피하고 "문서로 확인되지 않는다"는 단서를 붙이는 경향 때문이다. 후속 개선 대상이다.

**채점 정정 (리뷰 반영)**
- 처음 채점에서 어려운 발매일 문항의 "일" 키워드(`' 2 '` 등)가 공백 제거 정규화로 `2` 가 됐다. 이 키워드는 같은 문항의 `2026` 안에서 저절로 맞았다.
- 그래서 키워드를 전체 날짜 표기(`10월 2일`, `2026-10-02` 등)로 바꾸고, 숫자만 있는 키워드는 연도만 허용하는 회귀 테스트를 넣었다.
- 저장된 답변을 새 키워드로 다시 채점했다. 질문이 바뀐 Q-meaning-04 한 문항만 새로 답했다. 수치는 위 표와 같다. 실제 답변의 날짜가 정확했기 때문에 결과가 부풀려지지는 않았다.
- 같은 리뷰에서 Q-background-02 의 너무 넓은 키워드(`2`, `two`)를 좁혔다. Q-meaning-04 는 정답이 제목에 이미 드러나 있어 질문을 꽃 색으로 바꿨다.

**채점 신뢰도**
- 키워드 채점과 LLM 판정의 일치율은 0.94~0.97이다.
- RAG가 어려운 문항에서 받은 "틀림" 2건은 실제로는 정답이다(「하나이 료」=花井諒, 「100回嘔吐」). 판정 모델이 표기·언어 차이에 흔들린 것이다.
- 그래서 F2015 비교에서는 두 채점을 함께 보고, 서로 어긋난 문항은 사람이 확인한다.
